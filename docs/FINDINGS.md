# 发现

四条主要结论，以及支撑它们的数字。所有指标为 balanced accuracy，主协议 K=2。

---

## 1. 数据量比模型架构更重要

同一套代码、同一个模型、同一套超参，只改变训练数据量：

| 训练样本 | prompt 数 | K=2 |
|---|---|---|
| 9,703 | 3,232 | 0.5684 |
| 96,993 | 34,800 | 0.8134 |

**+0.245，架构没变。**

这条决定了后续的实验顺序：在数据量没吃满之前，换模型、调超参都是次要的。

---

## 2. 上下文长度是真实变量

数据中位 479 词，但 512 token 只能装下约 431 个有效 token，
**63.9% 的样本被截断**；放宽到 1024 token 后仍有 **30.0%** 被截断。

| 长度 | 轮数 | K=2 | K=all |
|---|---|---|---|
| 512 | 1 | 0.8134 | 0.7973 |
| 512 | 3 | 0.8350 | 0.8317 |
| **1024** | **1** | **0.8421** | 0.8296 |

**1024 单轮就超过了 512 三轮**（0.8421 vs 0.8350），说明长度比多训几轮更划算。
验证集 10,926 条，标准误约 0.006，+0.0287 约等于 4 个标准误。

### 顺带验证：结尾是否有额外信息

既然 1024 下仍有 30% 被截断，自然的问题是「被截掉的部分里有没有信号」。

设计了一个**免训练探针**：对 70% 未被截断的样本，「取开头 1024」和「取前 511 + 后 510」
两种输入完全相同，因此任何差异都只来自那 30% 的长文本。

| 输入 | 全体验证 | 仅长文本（30%） |
|---|---|---|
| 开头 1024 | 0.8296 | 0.8237 |
| 前 511 + 后 510 | 0.8292 | **0.8282** |

长文本上 **+0.0044**，且这是在模型从未见过这种输入（分布外）的情况下拿到的，
说明结尾确实带信息。但整体只变化 `0.3 × 0.0044 ≈ 0.0013`，落在噪声内。

**结论：方向成立，但天花板不高**，因为 70% 的样本本来就全文可见。

---

## 3. 给强模型叠加弱专家，必然亏

这是本项目最反复出现的一条。

| 场景 | 做法 | 变化 |
|---|---|---|
| 二元判别器修补 | 针对混淆最重的 8 个配对，各训一个二分类头，只在该配对内重判 | **−0.0118** |
| 角度间隔损失（热启动） | ArcFace 替换交叉熵，3,600 步 | −0.0091 |
| 角度间隔损失（严格 A/B） | 同起点、同步数、同超参，仅换损失 | **−0.0400** |

### 二元修补为什么失败

二元头只在「真实标签属于该对」的样本上训练，但推理时被应用在
「**预测**属于该对」的样本上 —— 其中有相当一部分真实标签是第三类，
二元头被迫在两类里选，把原本可能正确的预测改坏。

更根本的是信息量：二元头只见过 2 类，没有 18 类的对比上下文。
**用更弱的模型覆盖更强的模型，收益必然为负。**

### ArcFace 为什么失败

严格 A/B（同预训练起点、6,062 步、同 bs/lr、仅换损失）得 0.8021，
比普通交叉熵的 0.8421 低 0.040。

训练损失到最后仍有约 2.6（换算后），说明**它根本没拟合上**。
推测机理：18 类细粒度 + 10:1 不平衡 + 只有 1 轮训练预算，
角度间隔让优化变难，而交叉熵在同一预算下能走到更好的解。

> 值得记录的是：这个实验第一次做的时候同时改了四样东西（损失、步数、采样、标签平滑），
> 失败后无法归因。第二次做了严格单变量对照，才得到可信结论。

## 4. 集成看的是信息差异，不是方法差异

| 成员 | 单独 K=2 |
|---|---|
| CE @ 1024 tok | 0.8421 |
| ArcFace @ 1024 tok | 0.8330 |
| CE @ 512 tok（3 轮） | 0.8350 |

| 组合 | 最优 K=2 | 权重 |
|---|---|---|
| CE1024 + ArcFace1024 | 0.8488 | 0.7 / 0.3 |
| **CE1024 + CE512** | **0.8536** | 0.6 / 0.4 |
| ArcFace1024 + CE512 | 0.8533 | 0.4 / 0.6 |
| **三者** | **0.8580** | 0.5 / 0.2 / 0.3 |

关键在于第二行：**两个都使用普通交叉熵、只有输入长度不同的模型，
集成效果（0.8536）好于「换损失函数」的组合（0.8488）。**

也就是说，让模型**看到不同的信息**（不同长度的文本），
比让它**用不同的方法学习同样的信息**，能产生更互补的错误。

### 错误重叠

CE1024 与 ArcFace1024 在 K=2 子集上：

```
CE 错        847
ArcFace 错  1111
同时错       712
仅 CE 错     135   ← ArcFace 修好了这些
仅 ArcFace 错 399
```

ArcFace 自己多错 399 个，但确实修好了 CE 的 135 个。按 0.7 : 0.3 加权后收益为正。
**这就是「更弱的模型也能进集成」的原因 —— 前提是它的错误不重叠。**

## 附：18 个模型的可分性结构

在 0.8350 的模型上统计（验证集 23,953 条，plain accuracy 0.871）：

| 前 N 个混淆对 | 覆盖的错误占比 |
|---|---|
| 5 | 21.5% |
| 10 | **36.7%** |
| 20 | 56.3% |
| 30 | 68.4% |

错误不是均匀分布，而是集中在四个小圈子里：

```
圈 1  gpt-5.6-sol ↔ luna ↔ terra         同族三兄弟互混
圈 2  gemini-3.7-flash ↔ 3.8-flash        同族两代
圈 3  claude-opus-4-8 ↔ claude-fable-5    同族
圈 4  kimi-k3 ↔ glm-5.3 ↔ claude-fable-5  跨厂商
```

最大的单点混淆是 **kimi-k3 → glm-5.3（157 次）**，跨厂商。

召回率最低的模型：

| 模型 | 召回 |
|---|---|
| gemini-3.7-flash | 0.636 |
| kimi-k3 | 0.653 |
| gemini-3.8-flash | 0.669 |
| glm-5.3 | 0.709 |
| claude-fable-5 | 0.712 |
| gemini-3.6-flash | 0.774 |

两点观察：

1. **越新的模型越难认**：gemini 3.6-flash 有 0.774，而 3.7 / 3.8 掉到 0.636 / 0.669。
2. **混淆不按厂商归类**：kimi、glm、claude-fable-5 三家不同厂商的模型互相混淆最重，
   说明「文风相似」跟公司归属无关，更可能跟训练数据分布与对齐策略有关。
